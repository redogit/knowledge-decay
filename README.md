# Knowledge Decay
## Learning, identity, and parts of a whole

Knowledge Decay is a human-centered research practice: leave a habitual frame of thought, notice surviving fragments, imagine a different explanation, test what can be tested, and retain a way back to the question and evidence.

It is not reduced here to software, biology, mathematics, or a theory of communal behavior. Those are possible instruments and applications, not substitutes for the human purpose.

### The current question

How can parts remain identifiable, revisable, and informed about their position within a whole, while preserving meaningful relationships, uncertainty, failures, and recovery paths?

The original research wording is preserved in [CURRENT_RESEARCH_WORDING.txt](research/CURRENT_RESEARCH_WORDING.txt). The requirements are:

| Requirement | Intended responsibility |
| --- | --- |
| Self-identifying; strict identity | Distinguish an object, occurrence, revision, content digest, and interpretation. |
| Self-updating | Propose and check a successor; retain its predecessor and recovery route. |
| Self-reflecting | Compare purpose, observation, inference, failure, and unresolved remainder. |
| Self-pathing | Name the reason, conditional next steps, stopping condition, and way back. |
| Self-mapping | Preserve typed part-whole and dependency relationships. |
| Strict clarity | Make scope, assumptions, meanings, versions, and unknowns explicit. |
| Accountable grouping | Declare the membership criterion; retain nonmembers, overlap, and unknown membership. |
| Shared language format | Preserve original expressions within a versioned semantic contract. |

These operational descriptions are proposals. In particular, "equally informed" has not been silently replaced by identical information or role-specific sufficiency. The [requirement map](research/REQUIREMENT_MAP.json) preserves the distinction.

### Evidence boundaries

Keep **theory, definition, theorem, corollary, deduction, intuition, hypothesis, and experiment** distinguishable. A source's `PROVED` label is retained as source wording; it does not become a new verification result here. Several arguments require the explicit qualifications already recorded.

`RELATED != IDENTICAL`  
`METHOD_TRANSFER != EVIDENCE_TRANSFER`  
`SELF_REFLECTION != INDEPENDENT_CORROBORATION`  
`SOFTWARE_VERIFICATION != MATHEMATICAL_PROOF`

These are project guardrails, not numerical equations or blanket equivalence theorems.
